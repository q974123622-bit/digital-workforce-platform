# 企业知识查询与问答（enterprise-knowledge）

本技能用于处理「企业知识」类问题。技能只负责「如何查询、如何整理与如何诚实作答」，不负责「谁有权限」；访问控制由运行时统一治理链（Identity → Policy Engine → Plugin Gateway）决定。

## 执行流程

1. 先澄清与界定：确认用户真正要问的问题、范围和目标知识来源。如果问题含糊，先向用户确认，而不是自行猜测。

2. 判断是否需要检索：涉及企业事实、内部制度、流程、文档、FAQ 或业务说明时，必须走知识查询，不得依赖模型记忆编造。纯常识、无需内部知识的问题可直接回答，并说明这是通用常识而非内部检索结果。

3. 选择工具：只使用当前运行时实际可见、已授权的知识查询工具。若环境中暴露的正式工具名为 `search_knowledge`，则使用 `search_knowledge`。不要调用未注册、未授权或不可见的工具，也不得通过切换工具、改写查询表达、调用其他 Agent 等方式绕过。

   若任务需要比较外部监管与内部制度，且当前运行时暴露正式工具名为 `compare_regulations`，则使用该 Workflow；否则继续使用 `search_knowledge`。

   当任务明确是「监管 / 制度变更影响分析」，且当前运行时暴露正式工具名为 `analyze_policy_change` 时，可以使用该 Workflow 收集文档、外部监管、内部制度、证券业务与员工协作证据；该工具只负责收集结构化证据，最终影响判断与总结仍由本技能基于 Demo 数据完成。

4. 处理工具结果：
   - Allow / 正常结果：基于返回内容作答。
   - Deny：明确告知用户当前身份无权访问该资源，并保留返回的拒绝原因；停止本次检索，不继续尝试。
   - Approval Required：告知用户该操作需要审批，不假装已经取得结果。
   - Empty / Not Found：说明目前没有足够资料，不补造内部事实。
   - Tool Error：说明查询失败，不得把失败解释成「没有相关制度」。

5. 多来源结果处理：优先采用与问题直接相关的内容；不把不同来源相互矛盾的内容强行合并；出现冲突时，明确说明来源之间存在不一致。

6. 输出时区分三类信息：
   - 检索得到的事实；
   - 基于事实的整理与总结；
   - 当前无法确认的内容（需明确标注）。

7. 权限边界：本技能不判定员工权限，也不在正文中固化正式/实习、L1/L2、部门、策略编号等差异。所有访问控制以运行时 Policy 的返回为准。

## 职责边界

- Skill 负责：判断是否检索、如何调用工具、如何解读结果、如何诚实作答。
- Tool 负责：真正访问知识源并返回结果或拒绝原因。
- 如果当前运行环境没有可用的知识查询工具，本技能必须停止知识检索流程，明确告知用户「当前环境缺少可用的知识查询工具」，不得假装完成查询。
