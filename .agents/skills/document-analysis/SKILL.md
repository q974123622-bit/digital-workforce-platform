# 文档分析（document-analysis）

本技能只规定「如何分析文档」，不实现文档读取能力。是否真的能读取文档，取决于当前 Runtime 提供的文档读取、文件或知识查询 Tool；权限判定仍由运行时统一治理链负责。

## 执行流程

1. 先明确任务类型：
   - 总结；
   - 要点提取；
   - 问答；
   - 对比；
   - 风险/问题定位；
   - 结构化抽取。

2. 只使用当前 Runtime 实际提供的文档读取、文件或知识查询能力；不要假定存在某个具体 Tool。

   若环境中暴露正式工具名为 `read_document`，则使用它读取文档，参数为 document_name。

   若任务是文档与合规依据的联合分析，且当前运行时暴露正式工具名为 `review_document_compliance`，可调用该 Workflow 收集证据；最终分析仍由本技能完成。

3. 当前没有文档读取 Tool 时，明确告知无法读取文档，不得假装已经读过。

4. 不得凭文件名推测内容；文件名不是内容证据。

5. 文档内容为空时，明确说明「无有效内容」，不要把空文档解释成某种结论。

6. 两份文档存在冲突时，分别陈述两方内容，明确指出冲突点，不得强行选择其中一方当作事实。

7. 输出时区分：
   - 文档中的明确事实；
   - 基于事实的整理；
   - 推断或建议；
   - 无法确认的内容（需明确标注）。

8. 不使用任何真实公司内部文档；所有内容必须来自当前 Runtime 提供的虚构或已授权文档。
