## 一、一句话现状

- **有什么**：AI员工底座已建成并真机验证——模型网关连通、内部知识引擎三个库真实检索命中、插件市场「申请 → 审批 → 授权 → 执行」端到端跑通；后端 250 项、前端 81 项测试通过，可在无公网环境离线交付。
- **到哪了**：业务价值仍停在「单次问答」和「一次性群聊协作任务」，尚未进入真正的业务流程。
- **缺什么**：①原子能力写死在代码里，业务系统基本未接；②没有「流程 / 任务」这个一等公民；③记忆没有任务维度。

**优先级口径**

- **P0（审核类，需求三/四）**：单点闭环、现有能力基本能承接、不依赖外部系统，见效最快。
- **P1（任务流形态，需求一/二 + 原子能力层 + 任务级记忆）**：形态最完整，但强依赖外部接口与企微主动推送权限。
- **P2（大圆 / workbuddy 接入、人机协同嵌入）**：依赖腾讯灰度与外部侧接口。
- **P3（个人容器产品化）**。

**四条业务线本质是同一件事**：一份 SOP / 审核要点 → 按节点持续执行 → 查得到进度 → 通知得到人 → 留得下痕。差别只在周期（分钟级 vs 周月级）、干系人（两人 vs 多单位多层级）、触发（人提交 vs 定时/事件）。

## 三、需要一起定下来的问题

**优先级**
1. 先做**审核类**（单点闭环、见效快），还是先做**任务流形态**（形态最完整、但外部依赖多）？
2. 沉睡客户激活 SOP 是作为任务流的样板一起做，还是等任务流内核成形后再套用？

**外部依赖**
3. 企微「大圆」的 MCP / CLI 接入文档与凭据，什么时候能拿到？月底灰度结束后是否具备接入条件？
4. workbuddy 侧是否有可对接的接口？「workbuddy 作为内外部 MCP / CLI 中枢」这条链路，平台侧与 workbuddy 侧的分工怎么定？
5. 企微**主动推送**（通知干系人）需要什么应用权限与配额？目前只有被动回复能力。
6. OA / CRM / 数仓 / 问效 / WECOM / MOT 中，哪几个能先给接口或测试凭据？这直接决定原子能力的接入顺序。

**边界与口径**
7. 内部数据等级与云端模型的使用边界：哪些数据可进模型、哪些必须留本地？（平台已有数据等级控制能力可承载）
8. 审核类的责任边界：AI「建议判定」与「最终判定」的区别？哪些条目必须人工复核、复核人是谁、结论如何留痕？
9. 「每个会话就是一个工作流」在团队协作场景下的形态：共享一个会话，还是各自有会话、由任务串起来？（需专项调研）

**资料补充**
10. `AI审核要点案例.xlsx` 原件——审核要点与案例的核心输入。
11. 厦门任务流的完整流程图与责任单位口径（目前只有一张样板图）。

| 术语 | 含义 |
| --- | --- |
| 分身（DT-xxx） | 每位真人对应的 AI 身份，是本人的对话组织者 |
