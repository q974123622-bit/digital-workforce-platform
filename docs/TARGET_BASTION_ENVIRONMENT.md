## 2. 总体评估

目标堡垒机具备运行当前 AI 员工平台离线容器包的基础条件：CPU、内存、Docker Engine、Docker Compose、存储驱动、Docker 权限及磁盘容量均满足当前 MVP 部署要求。

当前需要在部署时处理以下事项：

1. 默认端口 `8080` 已被占用，应将平台入口端口改为其他空闲端口，例如待复验的 `18080`。
2. DWP 离线镜像尚未加载，需要通过离线发布包导入。
3. 首次网络预检返回域名解析失败；模型网关已确认在内部网络存在并可访问，仍需使用测试环境的实际地址复验。
4. 内部知识引擎和内部 mem0 尚未完成目标机联调，首轮部署分别使用 `mock` 模式，后续通过配置与 Adapter 接口切换。
5. `/home` 仅有约 9.8 GiB 可用空间，发布包、源码和运行数据建议放在容量更大的 `/app` 文件系统中。

综合结论：**环境基础条件通过，可以进入离线包上传和部署阶段；真实 Agent 问答需在部署时完成模型网关配置和连通性复验。**

### 5.3 部署目录建议

建议使用：

```text
/app/dwp-ai-employee-platform
```

不建议将完整发布包长期放在 `/home`，原因是镜像压缩包、解压文件和 Docker 导入过程可能产生多份临时数据。正式上传前需要确认当前部署账号对 `/app` 或指定子目录具有读写权限。

运行数据、插件文件和持久化数据应使用明确的子目录，不应直接写入 `/app` 根目录：

```text
/app/dwp-ai-employee-platform/
├── release/       # 离线发布包和启动脚本
├── source/        # 可选的完整源码，用于现场调试
├── config/        # 本机配置；禁止提交真实 Secret
├── data/          # 数据库、插件产物和运行数据
├── logs/          # 受控运行日志
└── backup/        # 备份输出
```

### 9.1 运行模式建议

```dotenv
DWP_AGENT_EXECUTION_MODE=harness
DWP_KB_MODE=mock
```

```dotenv
DWP_KB_MODE=internal
```

```dotenv

```

模型网关是生成真实回答的必要依赖；内部知识引擎和 mem0 在首轮 MVP 中可以分别使用 Mock Adapter，不阻塞页面、账号、插件、执行轨迹和基础 Harness 验收。

## 11. 可修改接口与现场调试条件

目标机具备 `git`、Docker 和 Compose，可以在保留完整源码的情况下修改知识库、mem0 和 MCP Adapter。推荐保持以下调用边界：

```text
Harness
  → 平台 Tool Gateway
  → Identity / Plugin Grant / Policy
  → KnowledgeAdapter / MemoryAdapter / MCP Adapter
  → Mock 或内部服务
  → Audit
```

现场调试只应修改配置或对应 Adapter，不应让业务代码和 Harness 直接请求内部服务。配置规则如下：

- 地址、认证、租户信息和 Secret 只保存在目标机 Git 忽略配置或公司 Secret 系统中；
- 不将真实值写入源码、Compose、镜像、测试、日志或审计；
- 自动化测试使用 MockTransport，不访问正式内部服务；
- Internal 模式异常时明确报错，不静默回退 Mock；
- 知识检索保持 `enable_filters=true`；
- 知识库访问同时校验插件绑定和具体知识库授权。
