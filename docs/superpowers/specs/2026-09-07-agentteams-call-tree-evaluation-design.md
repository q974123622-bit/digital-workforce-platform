# AgentTeams 协作调用树与双重评测设计

## 目标

把现有卡片式任务与三栏关系清单合并为一棵基于真实任务、依赖和消息数据生成的协作调用树，并为终态任务提供规则评测和 DeepSeek 质量评测。修正严格 Matrix 健康检查把心跳过期误报为 Matrix ID 无效的问题。

## 事实边界

- 树只消费服务端返回的任务节点、父子边、依赖边和持久化消息，不生成演示关系。
- 规则分由后端根据节点、依赖、消息、Tool 结果和审计编号确定性计算。
- 模型分是独立的 LLM-as-judge 参考分，使用 Manager 的 DeepSeek Key 发起单独调用；失败时保留规则分并明确标记模型评测不可用，不计算百分制总分。
- 完整评测以 `task.evaluation.completed` 事件写入现有 `agent_task_event`；模型暂不可用时写入 `task.evaluation.partial`，下次请求会重新评测，不新增数据库表。
- 不改变 Manager、Worker、Matrix 协议、Gateway 或任务状态机。

## 协作调用树

根节点展示可重新选择的 Manager 任务。子任务按 `task.delegate` 中的轮次分组，并在轮内按真实依赖做拓扑分层：同层节点并排，后继节点放到下一层。每个任务节点显示执行 Agent、状态、Tool 和 Gateway/审计结果。节点下的消息按照创建时间排列并翻译为中文，展示 `发送者 → 接收者：消息含义`。原有“父子委派 / 任务依赖 / 消息关系”三栏模块移除。

## 评测

规则评测满分 60：任务完成 10、有效拆解和派发 10、并行/串行/后续派发 15、Tool 经 Gateway 且有审计 15、消息送达和依赖满足 10。

模型评测满分 40：任务拆解 10、Agent 选择 10、根据子结果继续判断 10、最终答案质量 10。接口只接受已登记、无用户补充材料的两套虚构 Demo。发送给模型的上下文只包含固定场景说明、Manager Skill 说明、Agent 职责、任务标题与受控指令、消息类型、Tool 名称、Gateway/审计状态和最终答案，不包含 Tool 原始结果、Token、Key、URL 或认证信息；邮箱、手机号、身份证号等常见个人信息命中后也不会发起模型评测。提示词声明固定 JSON 契约，返回后继续由 Pydantic 和分值合计规则校验；失败后重试一次。

`POST /api/v1/agentteams-collaboration/tasks/{task_id}/evaluation?actor_no=...` 对终态任务执行或返回已缓存评测。非终态返回 409。评测结果包含规则分、模型状态、模型分、总分、逐项理由和扣分原因。

## 健康状态

严格模式保留 Manager 和 Worker 的真实运行状态：`ready`、`configured`、`unavailable`、`stale_heartbeat`、`invalid_runtime_binding`、`invalid_matrix_user_id` 或 `missing_runtime_ref`。前端只有在状态为 `ready` 时显示绿色“已就绪”；仅配置完成时显示“已配置”。当前任一 Agent 进程停止时，应显示“未运行或心跳已过期”，不能误报 Matrix ID 无效。

## 页面布局

页面上方仍保留环境与提交表单。任务详情区域左侧为协作调用树，右侧依次为最终汇总、协作评测、当前节点状态。规则分和模型分分区展示；点击树节点查看该节点完整消息和状态。

## 验收

- 严格健康接口能区分无效 MXID 与过期/缺失心跳。
- 已完成任务能生成并再次读取同一份持久化评测。
- 模型不可用时规则分仍可展示，且不伪造总分。
- 模型暂不可用后可以重新评测，只有完整模型分会作为完成缓存复用。
- 前端不存在旧三栏关系图，协作消息按任务归入树中。
- 前后端定向测试、前端类型检查和相关全量测试通过。
