## AI-AUDIT 的自主行为（第 11 项细节）

输入只有：persona + 「材料包已物化到 /workspace/materials，材料类型没有预设，需要你自己判断并写回」
+ 三份材料的转写文本。**没有给任何技能包、没有给任何步骤**。90 秒完成，实际行为：

1. **自己判材料类型并写回材料文件**：营业执照 → `material_type=企业营业执照`、
   工商公示信息截图、开户合同签字页（工作区文件里可见）。
2. **自己决定核对范围**：把「营业执照 vs 工商公示信息」做逐字段交叉核对，
   而不是按任何预设字段表逐条走。
3. **结论分三类并带来源与位置**：不一致（统一社会信用代码末位 8/B、企业名称、法定代表人
   测式/测试、注册资本 105.32 万 vs 1000 万、成立日期 1949 vs 2022、住所、经营范围）、
   待确认（企业类型括号内说明缺失、登记机关未转写出内容）。
4. **看不清就说看不清**：开户合同签字页的公章标注 `[[UNREADABLE]]`，答复里如实写「看不清（印章遮挡）」。

轨迹 79 个事件，其中 `materials_ready` 由平台侧在发起执行时发出，`attachment_search_*`
由附件工具发出，第 80 个事件是技能脚本上报通道灌进去的 `skill_step`（见第 9/10 项）。

## 一个未根因的开放问题

同一次执行最后**没有产出答复**：状态是 `completed`、`error_message` 为空，但一条
`answer_chunk` 都没有、会话里没有 assistant 消息。

**更正（当天晚些时候查库核对）**：这次「没有答复」是**读取方式造成的误判**，不是缺陷。
直接查 `conversation_message` 与 `agent_execution_event` 两张表：该执行有 **106 个
`answer_chunk` + 1 个 `answer_done`**，会话里有 3380 字的 assistant 消息（完整核对表）。
当时用 `/runs/latest` 只看到 11 个事件、`/conversations/{id}` 只看到 user 消息，
是接口在这个时刻的返回与我预期不一致（`/runs/{eid}/events` 实际是 SSE 流，
`runs/latest` 的 events 也不是全量），排查时被误导了。

dsh 会话日志（`unzstd -c session.v3.jsonl.zstd`）确认模型跑了 23 步、54 次工具调用、
写出两份核对表，第 24 步 `step/start` 之后没有 `step/end`。执行 02:49:45 → 02:56:24 = 399 秒。

**由此得到的结论**：`dsh` 在进程被截断时仍会把已产出的最终答复交给 stdout（本次答复是完整的），
所以「无答复」不是高频路径；但「无答复」确实可能发生（模型把预算全花在工具调用上、
或进程更早被终止），而产物就在工作区里。因此仍然实现了兜底（见下）。

## 无最终答复时的兜底（已实施）

dsh 是一次性 CLI 调用，最终答复只从 stdout 出来。没拿到答复时（模型把预算花在工具调用上、
进程被终止、stdout 为空），平台改为**读回工作区产物当答复**，而不是弹空气泡。

改动：

| 位置 | 改动 |
|---|---|
| `services/workspace_readback.py` | 新增。收集工作区里本轮动过的文本产物并渲染成兜底答复 |
| `services/runtime_adapter.py` | `RuntimeResult` 增加 `empty_output`：把「跑完了但没输出」和「容器起不来」区分开 |
| `services/harness_agent.py` | 无答复时读回产物、发一条 `answer_from_workspace` 轨迹事件、用产物替换答复；真失败照旧 503 |
| `services/group_chat.py` | 一条答复都没有时判 `failed` 而不是 `completed`（空答复不再被当成完成） |
| `harness_agent._prompt` + `SKILL.md` | 明说「结论必须写进答复正文，只写文件等于没交付」——从源头减少依赖兜底 |

三条约束（都是为了避免把过程文件、旧文件当成结论）：

1. **只读文本类产物**（`.md` / `.txt` / `.csv`）。`findings_*.json` 是工具之间的交换格式，
   贴给业务同事看没有意义，还会把整份规则表带出来。
2. **只读本轮动过的文件**（mtime ≥ 发起执行的时刻，留 5 秒时钟偏差余量），
   不把上一轮的旧核对表当成本轮结论。
3. **不读平台自己写的东西**（`skills/` 投放的技能包、`materials/` 物化的材料、隐藏文件）。
   单文件截断 6000 字符、整份答复上限 18000 字符。

拿真机上模型留下的产物实测：读到 `核对表_B2026001.md`(15213B) 与 `核对表_B2026002.md`(14600B)
两份，JSON 中间件、`skills/`、`materials/`、隐藏文件全部正确跳过，渲染出 12183 字符的兜底答复。

新增 11 个用例（`tests/test_workspace_readback.py`）：过滤器、mtime、截断、上限、
渲染标注、真失败不兜底、无产物时仍判失败。
