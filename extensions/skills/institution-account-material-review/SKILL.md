# 机构开户材料交叉核对

对机构证券账户开户业务做材料比对审核：把系统录入侧与客户提交侧的材料逐字段交叉核对，输出「一致 / 不一致 / 待确认」清单。

材料是一堆**平铺**的文件，**哪些属于同一笔业务由你按材料内容判断**：`inspect` 会给一组「疑似同笔」的提示（`suggested_groups`），那只是提示、不是结论。判断完用 `--codes` 圈定本轮要核的材料 —— 逻辑分笔，不必搬动文件。

**系统录入侧截图（`M-SYS-xx`）与客户材料一样要抽字段取值** —— 它是比对的**基准方**，不是「字段全集来源」。系统侧取不到值，比对就只剩客户材料互相比对，单个来源会被判成「一致」，那种结论不可采信。`audit` 与平台的物化步骤都会自动抽一遍（含系统侧），你不用手动跑。

材料类型（`M-CUST-xx` / `M-SYS-xx`）不用你逐份翻材料手工判：`audit` 会按**文件名 / 转写文本**先给一个确定性猜测并写回材料文件，
返回里带 `type_guesses`（哪份、猜成什么、依据、相似度）。**只有明显猜错的那几份**才需要你改它的 `material_type` 再重跑。

**核哪些字段、按什么顺序核、先看哪份材料、发现异常往哪追、什么时候收尾，由你按材料实际情况自行决定。** 本技能给你的是工具与红线，不是流程。

## 首选：一条命令收尾（默认就该这么干）

材料包已平铺在 `/workspace/materials/<包>/`，直接跑：

```bash
python3 scripts/review.py audit --materials /workspace/materials/<包> --out-dir /workspace/output
```

它一次做完 补材料类型 → 抽字段取值 → 清点 → 比对 → 证据回查 → 出表，产出：

- `/workspace/output/核对表.md` —— 最终核对表（覆盖率闸门已跑过，**这就是你要交付的东西**）
- `/workspace/output/核对表.html` —— **同一份核对表的 HTML 版，默认就会产出**（不用加任何参数），
  可直接在浏览器打开、可直接打印；业务同事默认看的就是这一份
- `/workspace/output/findings.json` —— 完整结论，每条都带 `level` 与 `evidence_quote`（机器用，几十 KB，**不要 cat**）

`.md` 与 `.html` 都是本轮交付物，**两份都要留在 `/workspace/output/`** —— 平台会把它们一起收进产物卡片。
不要删掉 `.html`、不要把它另存到别的目录、也不要自己再拼一份 HTML。只有明确不要 HTML 时才加 `--no-html`。

**然后读一遍 `/workspace/output/核对表.md`，据此写答复，本轮即可收尾。**
`audit` 会自己把结果上报进执行轨迹，你不需要再手动调 `report_channel.py`。

退出码 0 且核对表存在，就说明这一轮该做的判定已经全部做完 —— 你的剩余工作只有「读表 + 写答复」两件事。

### 核对表已经包含什么（不要自己再写一份）

| 章节 | 内容 |
|---|---|
| 零、本轮材料完整性 | **先看这里**：缺哪几份必备材料 → 因此哪些字段无法比对；材料已提供但缺栏目（字段名没对齐）另列一档；未核字段按缺口归并 |
| 一、比对材料清单 | 每份材料的代号 / 名称 / 系统侧或客户侧 / 用途说明（抽取字段数、是否参与比对、必备性）；缺失材料与被排除材料单列 |
| 二、结论摘要 | 字段总数、必核数、一致率（带分子分母）、覆盖率（带分子分母）、各分级计数、**系统录入侧取值覆盖**（基准方全空时在这里显式告警） |
| 三、不一致 / 待确认汇总 | A 严重风险（材料级）｜B 字段级不一致｜C 待确认｜D 印章签章；**来源材料并列成列**的宽表 |
| 四~八、逐份系统侧材料明细 | 每张截图一节，**逐字段**列出各来源取值与核对结果（含未核字段） |
| 九、客户侧材料之间的专项比对 | 系统侧取不到值、实际由客户材料互相印证的字段 |
| 十、材料清单及盖章情况 | 是否提供 / 公章 / 签字 / 备注 |
| 十一、核对结论 | 需优先处理、其他需处理 |
| 十二、判定规则说明 | 分级口径、材料级问题编号、截断与列口径 |

**材料不齐时它会在第一节就把缺口说清楚**（缺哪份、卡住多少字段），不需要你在答复里另行推断。

## 效率红线（违反只会拖慢这一轮，不会提高准确率）

- `audit` 已经把材料类型、字段抽值、清点、比对、证据回查、出表全部做完，结论都在 `核对表.md` 里。
  **不要再逐份读材料 JSON、不要 cat `findings.json`、不要再整包重跑 `extract` / `compare` / `report`。**
  这些动作不会让结论更准，只会把上下文撑大、让每一轮都更慢。
  例外只有一处：**某一份**材料的取值明显抽错时，用
  `review.py extract --materials <包> --material <代号> --write` 只重抽那一份。
- **禁止自己写比对脚本、也禁止自己另写一份报告**。真机上出现过：模型绕过本技能，
  在工作目录里自建 `extract_fields.py` / `cross_check.py` / `compare.py`，又手写了一份
  核对表。结果是 —— 判定口径与技能包不一致、报告结构与交付要求不符、
  整轮多花好几分钟，而且用户拿到的两份东西互相矛盾。
  `核对表.md` 已经是完整交付物：缺口、逐字段明细、宽表、印章、结论段都在里面。
  你要做的只有「读它 + 写答复」。
- 只有两种情况才用分步命令：① `audit` 报错或退出码非 0；② 你对**某一条**具体结论存疑 ——
  用 `verify --key <字段>` 单独回查那一条。
- 产物一律写独立输出目录（如 `/workspace/output/`），**不要写回材料包目录** ——
  那里是材料清单，写进去会覆盖它；而且下一轮扫描材料时会把产物当材料（材料清单里
  凭空多出一行 `findings`）。
- 命令输出本身就是 JSON，已经很长；不要再套 `head` / `python3 -c` 反复解析重试，一次调用拿全结果。
- 一次 `ls` 也不必：材料清单已随任务给出（`TASK_ENVELOPE.materials.catalog`），目录结构见上文。

## 铁律（不可违背）

1. 只提示不决策。所有结论一律标注「机器提示，以人工审核为准」，不得给出「通过 / 拒绝 / 可以开户」的最终判定。
2. 不猜。字段值只能来自材料转写文本，且必须能在原文命中；定位不到就留空，禁止凭常识补全、禁止推断。
3. 判定由脚本给出，核对范围与顺序由你规划。归一化与判定一律跑 `review.py`，不要自己心算一致性；但先核哪些、按什么顺序、要不要回查，是你的决策。
4. 印章、签字类只出「有 / 无 / 看不清」三态，不给一致性判定。
5. 证件号、账号等敏感信息不得写进日志、不得外发。上报轨迹统一走 `report_channel.py`（自动打码长数字串）。

**结论必须写进答复正文**：核对表落盘是为了留痕，但用户只看得到你的答复。
把文件当交付、答复里只说「已生成核对表」等于没交付 —— 摘要、不一致明细、
待人工确认项都要在答复里直接给出。

**同时要交代产物**：答复末尾用一句话说明「核对表已生成 Markdown 与 HTML 两版，
可在产物卡片里直接预览 / 下载 / 打印」。HTML 是默认产出的，不需要用户再要求。

**答复控制在 800 字以内**（一张摘要表 + 不一致明细 + 待人工确认项即可）：
完整核对表已经在文件里，答复是把结论讲清楚，不是把文件抄一遍。
逐条罗列几十行只会让用户读不下去，也让这一轮白等更久。

## 工具清单（需要复核某一步时才用）

脚本在 `scripts/`。除 `report` 外一律 stdout 输出 JSON；每个子命令都无状态、可重复调用、可只跑一部分。

| 命令 | 用途 |
|---|---|
| `review.py audit --materials <材料包目录> [--codes D1,D2] [--fields a,b] [--out-dir 目录] [--force] [--no-extract] [--html [路径]] [--no-html]` | **一站式（首选）**：补材料类型 → 抽字段取值 → 清点 → 比对 → 证据回查 → 出表，直接产出 `findings.json` 与 `核对表.md` **与 `核对表.html`（默认两份同出）** |
| `review.py verify --materials <目录> --findings findings.json [--key K] [--codes D1,D2]` | 只回查证据：结论引用的原文是否真的命中（存疑时用这一条） |
| `review.py inspect --materials <材料包目录> [--codes D1,D2]` | 清点材料 + 每份摘要（类型、载体、转写行数、指纹、前几行）+ 疑似同笔业务提示 |
| `review.py rules --kind index\|fields\|materials\|rules\|synonyms [--key K] [--group G] [--rule R] [--material M]` | 按需查字段定义与规则口径 |
| `review.py extract-all --materials <材料包目录> [--codes D1,D2] [--force]` | 整包批量抽值（含系统侧）：只补材料里还没有的字段，不覆盖已有值；返回每份材料的产率与低产率告警 |
| `review.py extract --materials <目录> --material <代号> [--fields a,b] [--labels JSON] [--write]` | 对指定材料、指定字段做确定性定位抽值，产出可命中的 evidence_quote（某一份抽错时用它重抽） |
| `review.py compare --materials <目录> [--codes D1,D2] [--fields a,b] [--groups G] [--out findings.json] [--append]` | 比指定字段或字段组（`--codes` 圈定本轮材料），输出 findings |
| `review.py report --findings findings.json --out 核对表.md [--html [路径]] [--no-html] [--force]` | 渲染核对表（`核对表.md` 与 `核对表.html` 默认两份同出）；出表前强制跑覆盖率自检 |
| `report_channel.py --title "…" --detail "…" [--status running\|completed\|failed]` | 把「你做了什么」上报进执行轨迹（`audit` 已自动上报，一般不需要手动调） |

关键节点（开始核对、出表完成）各上报一次轨迹即可，不必每步都报。

## 分步路径（仅供复核，不是默认流程）

只有 `audit` 报错、退出码非 0，或你对某一条结论存疑时才走这条路：

1. `inspect` 清点，确认必备材料是否齐备；缺必备材料先提示补件。
   如果材料里不止一笔业务，先按 `suggested_groups`（或你自己的判断）用 `--codes D1,D2,S1` 圈定本轮要核的那笔，再往下走。
2. 自己判断每份材料的类型；需要补抽字段就 `extract-all`（整包补抽缺失字段，含系统侧），
   单份可疑时用 `extract` 只重抽那一份。
3. `compare` 比对（可以只比一组、反复比、`--append` 累积成完整结论）。
4. 对结论有疑问的用 `verify` 回查证据。
5. `report` 出核对表，再回话：结论摘要 + 不一致明细（四要素）+ 待人工确认项。

材料实际情况与这条路径不符时，按你的判断来。

## 出表前的自检清单

核对表自己已经满足下列各条（渲染器负责），你只需要在答复里对上口径：

- 必核字段是否都被核到？未核的必须显式列出「未核 + 原因」（`report` 会拦住，除非 `--force`）
  —— 第一节按「缺哪份材料 / 哪份材料缺该栏目」归并给出。
- 每条结论是否带「字段名 + 来源材料 + 材料上的位置 + 归一化前后取值」四要素？
  —— 逐字段明细节的宽表逐列给出。
- 不一致项是否给了差异性质（错填 / 漏填 / 口径不同 / 材料本身有问题）？
  —— 三 B 的「说明」列以 `[差异性质]` 开头。
- 材料级问题（非本户、材料内部矛盾、签章缺失）是否单独成章，没有和字段级混排？
  —— 三 A 与十。
- 是否复述了脚本日志？（不要复述）
