# 技能包测试与样例数据

两层测试，一层跑合成小样例验逻辑，一层跑真样例验行为。

## 一、离线自测（合成小样例）

```bash
python3 scripts/tests/test_skill_toolkit.py     # 77 项，纯 stdlib，不联网不调模型
```

现场造一笔最小业务（1 份系统录入侧 + 2 份客户侧）来验：清点、查规则、抽值、比对、
证据回查、覆盖率闸门、上报降级、多版本收敛、参考路径。跑完打印通过/失败数与失败清单，
失败时退出码 1。

## 二、真样例回归（`fixtures/`）

```bash
# 重新固化样例数据（数据源变了才需要跑）
cd 07_抽取评测 && python3 runner/build_sample_fixture.py
```

产物：

| 路径 | 内容 |
|---|---|
| `fixtures/sample-pack/100012798-full/` | 13 份材料 + `materials.json`，技能包工具链直接可跑 |
| `fixtures/sample-pack/100012798-sys/` | 系统录入侧子集（5 份），文本直读通路 |
| `fixtures/sample-pack/expected.json` | 逐字段期望值：golden 答案 + 评测抽取结果 + 证据引文 |
| `fixtures/sample-pack/coverage-baseline.json` | 样例集的覆盖上限声明（哪些必核字段这批材料本来就没有来源） |
| `fixtures/sample-files/` + `sample-files.zip` | 真实样例文件副本（含中文名、空格、括号），供平台侧解包测试 |

样例数据不是手写的，是从 **golden.json（人工确认过的答案）+ 评测产物（转写文本、抽取结果、
每份材料胜出的读取模式）** 固化出来的。这么做的好处是：测试不用跑模型就能覆盖真数据，
而且「评测产物 → 核对结论」这一段的一致性也被锁住了。

`test_skill_toolkit.py` 里的 `test_sample_pack()` 用这批数据验：

1. 清点出 13 份材料、类型全部识别、必备材料齐备、指纹稳定；
2. 全量比对 + 证据回查**零未命中**（含 4 条跨行引文按 `text` 口径命中）；
3. 评测基线锁定：69 条可导出字段 / 68 正确，唯一判错的是 F4 业务专用章
   （已知结构限制：椭圆章被电子签章水印打成马赛克）；
4. 确定性抽取器挡住界面控件文字（`AI`）与一行多字段（值止于下一个标签），
   且不误伤长证件号与纯数字；
5. 覆盖率闸门默认拦住出表、`--force` 才出表且保留未核章节；
6. `acceptance.py --baseline` 六项全过，覆盖率 = 0.6226；
7. **基线守卫**：把基线外的字段人为变成未核，验收必须判失败（证明闸门没放水）。

## 三、平台侧（解包与放行）

真样例打的 zip 在 `backend/tests/test_material_pack.py::test_real_sample_pack_unpacks`：
验按业务号分组、中文名/空格/括号还原、docx 混排、真实魔数判类型。
容器里跑测试时用 `DWP_SAMPLE_FIXTURE_DIR` 指到 `fixtures/`，找不到就跳过。

## 覆盖率的正确读法

样例材料集只覆盖整笔业务的一部分：规则表 93 个字段 / 53 个必核，这批 13 份材料只能覆盖
33 个必核字段（0.6226）。剩下 20 个（系统录入侧的手机、联系电话、联系地址、各类证件类别等）
的来源材料不在这批材料里 —— 这是**材料集局限，不是核对漏项**。

因此基线只声明这 20 个，`acceptance.py` 对基线之外的新增未核仍然判失败。
要提升覆盖率只有两条路：补材料（把缺的栏位拍进来）或在 golden 里补标注（需要人工确认答案），
两条都不该靠放水闸门解决。
