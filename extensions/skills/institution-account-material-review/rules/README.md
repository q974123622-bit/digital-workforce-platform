# 规则数据与可查询索引

本目录是**数据**，不是流程。脚本读取执行，不要凭记忆判断，也不要自己改写规则口径。

| 文件 | 内容 | 查询方式 |
|---|---|---|
| `fields.json` | 93 个核对字段：归属系统侧分组、来源材料与来源字段名、归一化编号、判定编号、是否必核 | `review.py rules --kind fields [--key K] [--group M-SYS-01] [--rule J-07] [--material M-CUST-01]` |
| `materials.json` | 材料类型登记：代号、名称、载体、必备性、该材料应抽取的字段名清单 | `review.py rules --kind materials [--key M-CUST-01]` |
| `rules.json` | P 前置校验 / N 归一化 / J 判定 / L 分级 / 印章严重度的编号定义 | `review.py rules --kind rules` |
| `synonyms.json` | 证件类别、机构类别、国有属性、诚信状态、是否、长期有效、空值三态的同义词组 | `review.py rules --kind synonyms` |
| —— | 紧凑索引：有哪些字段、是否必核、适用哪些材料（规划阶段先扫这个） | `review.py rules --kind index [--group M-SYS-01] [--name 证件]` |

## 结论口径（L 分级）

| 级别 | 含义 | 是否计入一致率分母 |
|---|---|---|
| L1 | 严重风险（如疑似非本户材料） | 否 |
| L2 | 不一致 | 是 |
| L3 | 待确认（单边为空、视觉三态、体系不同无法映射等） | 是 |
| L4 | 一致 | 是 |
| L5 | 系统独有（无外部来源可比） | 否 |

一致率 = 必核且判一致的字段数 / 必核字段数（必核且非 L5）。
另有**覆盖率**：必核字段中被真正核到（有来源）的比例；未核字段必须在核对表里显式列出原因，
否则 `review.py report` 会拒绝出表。

覆盖率还有一条**系统侧口径**：系统录入侧（基准方）某份材料一个字段都没抽出来时，闸门同样
不通过。系统侧是比对的基准方，不是「不用抽的字段全集来源」—— 它取不到值，比对就退化成客户
材料互相印证，单个来源会被判成「一致」。系统侧截图与客户材料走同一套抽值逻辑
（`extract-all`，`audit` 与平台物化步骤都会自动跑）。

判定侧的「单边为空」是双向的：系统侧有值、客户侧全没读出 → L3；系统侧该栏为空、客户侧有值
→ L3。只有基准方有值时**不算一致**。

## 改规则时注意

- 改了 `fields.json` / `rules.json` 的编号，必须同步 `scripts/normalize.py`（N-xx 实现）与
  `scripts/judge.py`（J-xx 实现），否则规则表与代码行为会漂移。
- 同义词表只影响 N-04 / N-07 两类归一化；新增枚举写法请加到**已有组内**，不要新建组，
  否则同一枚举会被判成两个不同体系。
- **来源要指对栏位**：`fields[].sources[].path` 必须是该材料里真正承载这个值的栏位名。
  真机上出过把营业执照的「类型」（企业类型）当成「证件类别」的来源，结果营业执照与系统
  录入被判不一致。改来源映射后跑一遍判定评测（`../判定评测/run_judge_eval.py`）确认没有回退。
- **系统侧不写 `sources`**：系统侧来源按 `system_group` + 字段 key 后缀自动对应，
  字段中文名同时充当系统截图的标签。
- 空值三态（`synonyms.json` 的 `empty_states`）里**不含「无」**：它是「不良诚信记录」这类
  栏位的正常取值，判成空值会让本该一致的两边落成待确认。
